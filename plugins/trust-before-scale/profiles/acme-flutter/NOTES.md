# acme-flutter

Invented Flutter + Firebase app. One gate: run the project CI script and capture its output.

These are invented examples, not excerpts from an application. Each seed adds a standalone file.
Adapt cases to your project before relying on an eval score. Keep the self-merge lane disabled until the owner accepts the ADR.

## Routine inputs

The routine configuration names Acme example rule, design-system and core-flow documents under
`docs/`. Replace them with your own real sources before relying on reviews. New pass cases add
standalone Acme documents alongside their changed file so the blind reviewer has project policy;
the prompt supplies the corresponding config inputs because the eval runner hides project config.
These are example requirements, not universal product rules. Staff and parent personas are examples.
The installer vendors scripts and cases; install the configured skills into `.agents/skills/`
from the plugin before running evals. Level 3 is required to validate suites.
